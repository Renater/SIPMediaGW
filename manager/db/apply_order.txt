# Order in which the schema files must be applied.
#
# Alphabetical order is not dependency order: schema_rates.sql defines a view
# over monthly_pool_hours, which schema_reporting_lot1.sql creates — and "rates"
# sorts before "reporting". Running `for f in db/*.sql` therefore fails, and
# fails halfway, leaving the schema in whatever state the transaction rolled
# back to.
#
# A test checks that every .sql file appears here, so a new one cannot be added
# without saying where it goes.

schema.sql
schema_org_units.sql
schema_pool.sql
schema_reporting_lot0.sql
schema_reporting_lot1.sql
schema_reporting_lot2.sql
schema_reasons.sql
schema_rates.sql
schema_users.sql
